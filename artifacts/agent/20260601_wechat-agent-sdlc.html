方法论 · 2026.06 · 架构驱动

Agent 时代，
软件开发全流程该怎么做？

5 阶段 9 步骤，每步定义 Input / Output / Activity / Actor。

Architecture Notes·2026 年 6 月·12 分钟阅读

核心判断

Human: Define → Constrain → Verify
Agent: Implement → Assemble → Iterate
Automation: Enforce → Monitor → Alert

开发流程不是「AI 替代某些步骤」，而是人类角色从「执行」转向「指定、约束和验证」。在代码写得越来越快的时代，约束比实现更重要。

· · ·
Phase A · 定义阶段

在 Agent 写下第一行代码之前，必须完成三个定义工作。

Step 1 · 需求分析与质量属性定义

不只是「功能列表」，而是显式定义质量属性目标。

→ Input

业务需求 / 用户故事
利益相关者期望
行业/合规约束

Output →

质量属性效用树
架构驱动因素
质量属性场景（可度量）

Quality Gate: 不是「要快」，而是「P99 < 200ms」。

Step 2 · 架构设计与决策

选择架构风格、划分模块边界、记录关键决策。

→ Input

质量属性效用树
架构驱动因素清单
团队技术栈

Output →

架构风格选型
模块分解图
ADR

Step 3 · 复用资产盘点与组件规划

Agent 时代杠杆率最高的步骤。

有组件目录 → Agent 直接复用 → 少写代码 → 少出 bug。

→ Input

模块分解图
现有组件库
开源可用组件

Output →

复用映射表
组件目录
复用率目标 ≥ 60%

· · ·
Phase B · 规约阶段

Step 4 · 接口契约定义

契约是人与 Agent 之间最重要的接口。

→ Input

模块分解图 + ADR
复用映射表

Output →

API 契约
数据 Schema

Step 5 · 测试规约

先写测试，再让 Agent 实现。

→ Input

功能需求
接口契约

Output →

验收测试
契约测试

· · ·
Phase C · 实现阶段

Step 6 · 增量实现（Agent 主导）

核心：组件搜索优先。

→ Input

接口契约
验收测试
组件目录

Output →

代码增量
单元测试
Diff

Quality Gate: CI 绿灯；复用率达标。

Step 7 · 架构符合性验证

验证模块边界、组件使用、耦合。

→ Input

代码增量
架构约束规则

Output →

架构合规报告
Review 意见

· · ·
Phase D · 验证阶段

Step 8 · 集成与端到端验证

契约测试 → E2E 测试 → 性能基线 → 安全扫描。

→ Input

通过验证的代码
契约测试套件

Output →

集成/E2E 测试报告
性能基线对比

· · ·
Phase E · 演进阶段

Step 9 · 知识沉淀与资产演进

  • 提取新组件 → 补充到组件目录
  • 更新 ADR → 补充隐含决策
  • 计算复用率 → 跟踪趋势
  • 复盘 → 哪些约束被绕过了？
  • 更新 Fitness Function
