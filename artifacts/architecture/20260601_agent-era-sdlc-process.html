方法论 · 2026.06 · 架构驱动

Agent 时代，
软件开发全流程该怎么做？

大模型 + Vibe Coding + Coding Agent，代码产出速度远超质量保障速度。
5 阶段 9 步骤，每步定义 Input / Output / Activity / Actor。

Architecture Notes ·2026 年 6 月 ·12 分钟阅读

核心判断

Human: Define → Constrain → Verify
Agent: Implement → Assemble → Iterate
Automation: Enforce → Monitor → Alert

开发流程不是「AI 替代某些步骤」，而是人类角色从「执行」转向「指定、约束和验证」。在代码写得越来越快的时代，约束比实现更重要。

· · ·
Phase A · 定义阶段

在 Agent 写下第一行代码之前，必须完成三个定义工作。

Step 1 · 需求分析与质量属性定义

不只是「功能列表」，而是显式定义质量属性目标——这些是 Agent 无法自行推断的约束。

→ Input

业务需求 / 用户故事
利益相关者期望
系统现有状态
行业/合规约束

Output →

质量属性效用树
功能需求清单（优先级排序）
质量属性场景（可度量）
架构驱动因素

Quality Gate: 不是「要快」，而是「P99 < 200ms」。架构驱动因素清单已获确认。

Step 2 · 架构设计与决策

基于架构驱动因素，选择架构风格、划分模块边界、记录关键决策。

→ Input

质量属性效用树
架构驱动因素清单
现有系统架构
团队技术栈和运维能力

Output →

架构风格选型 + 理由
模块/子系统分解图
架构决策记录 (ADR)
架构多视图文档

Quality Gate: ADR 已通过评审；选择对 Agent 友好的风格。

Step 3 · 复用资产盘点与组件规划

这是 Agent 时代杠杆率最高的步骤。

有组件目录 → Agent 直接复用 → 少写代码 → 少出 bug。

→ Input

模块分解图（Step 2）
现有组件库 / Design System
开源可用组件
组织内部已沉淀的服务

Output →

复用映射表
组件目录 (Catalog)
需新建组件清单
复用率目标（≥ 60%）

Quality Gate: 每项需求已有明确的复用/新建判定；组件目录可被 Agent 检索。
· · ·
Phase B · 规约阶段

Step 4 · 接口契约定义

契约是人与 Agent 之间最重要的接口。

→ Input

模块分解图 + ADR
复用映射表
需新建组件规格
质量属性约束

Output →

API 契约文档
内部接口定义
数据模型/Schema

Step 5 · 测试规约与验收标准

先写测试，再让 Agent 实现。

→ Input

功能需求 + 质量属性场景
接口契约（Step 4）
复用组件已知行为

Output →

验收测试（Given-When-Then）
契约测试定义（Pact 等）
性能/安全测试基线

· · ·
Phase C · 实现阶段

Step 6 · 增量实现（Agent 主导）

核心原则：组件搜索优先。

→ Input

接口契约（Step 4）
验收测试（Step 5）
复用映射表 & 组件目录
编码规范与架构约束

Output →

可运行的代码增量
单元测试（Agent 自动生成）
增量 Diff（供 Review）

Quality Gate: 增量 ≤ 一个 Review 会话能评审的体量；CI 绿灯；复用率达标。

Step 7 · 架构符合性验证

不是逐行 Review 逻辑，而是验证：模块边界、组件使用、耦合。

→ Input

代码增量（Step 6）
架构约束规则
接口契约（比对基准）

Output →

架构合规报告
Review 意见
需修正的问题清单

· · ·
Phase D · 验证阶段

Step 8 · 集成与端到端验证

契约测试 → E2E 测试 → 性能基线 → 安全扫描。

→ Input

通过符合性验证的代码
契约测试套件（Step 5）
性能/安全基线

Output →

集成/E2E 测试报告
性能基线对比
遗留问题清单

Quality Gate: 所有契约测试通过；核心 E2E 场景绿；性能无退化。
· · ·
Phase E · 演进阶段

Step 9 · 知识沉淀与资产演进

  • 提取新组件 → 补充到组件目录
  • 更新 ADR → 补充隐含决策
  • 计算复用率 → 跟踪趋势
  • 复盘 → 哪些约束有效？哪些被绕过了？
  • 更新 Fitness Function → 新违规模式加入自动化检查
