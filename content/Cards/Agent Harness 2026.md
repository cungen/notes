## skills

- **技能定义（一句话）**
  Skill 是一组可复用的任务指令与上下文包（通常以 `SKILL.md` 为核心），让 Agent 在遇到匹配任务时按约定流程执行。

- **`claw-code` 如何发现并使用技能**
  - 技能认知来源（不是单一静态清单）
    - 通过运行时可见工具建立“可用能力感知”（如 `Skill`、`ToolSearch`）。
    - 通过指令上下文（如 `CLAUDE.md` / `.claw/instructions.md`）获得“何时该用技能”的策略提示。
  - 技能发现流程
    - 从本地多个目录动态扫描技能根路径（如 `.claw/skills`、`.omc/skills`、`.agents/skills` 等）。
    - 读取对应 `SKILL.md` 并解析名称/描述等信息用于匹配与校验。
  - 技能执行流程
    - 模型在对话中判断任务匹配后，可主动调用 `Skill` 加载目标技能。
    - 若技能名不准确，解析/错误反馈会帮助模型回退并选择正确技能。
  - 结论
    - 即使用户没显式说“用某个 skill”，Agent 仍可能主动命中并使用合适技能。

- **`openclaw` 如何发现并使用技能**
  - 技能发现与整理
    - 先聚合多来源技能目录并解析 `SKILL.md` 元信息。
    - 在运行前构建技能快照，并结合配置进行过滤/排序。
  - 技能注入与选择
    - 将可用技能信息（类似 `available_skills`）注入提示词上下文。
    - 引导模型先从已知可用技能中做选择，再读取目标技能内容。
  - 技能执行
    - 选定技能后读取 `SKILL.md` 指令并进入工具调用/执行环节。
  - 结论
    - 更接近“先给技能目录，再按规则选择并执行”的显式技能路由模式。

## tools

### ClawCode 里的 ToolSearch
- **`ToolSearch` 是什么（一句话）**
  `ToolSearch` 是用来在当前可用工具里做检索的能力，输入查询后会返回最相关的工具名称列表，帮助 Agent 快速选到合适工具。

- **工作流**
  - 收集可搜索工具：内置工具、运行时已注册工具、插件工具。
  - 接收查询并做标准化处理（例如大小写和别名统一）。
  - 执行匹配与排序（支持精确选择和关键词匹配）。
  - 返回结果列表，并附带查询相关状态信息（例如某些 MCP 服务当前不可用）。

- **使用条件与边界**
  - 适合用于“我该调用哪个工具”这类工具发现场景。
  - 能检索到已注册到运行时的 MCP 工具。
  - 不能直接检索技能目录里的普通脚本或文档内容（除非它们已被注册为工具）。
  - 当外部工具服务异常时，仍可返回结果，但会带出降级/待恢复状态。
